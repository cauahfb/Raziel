# Raziel — refinamentos de novembro/2026

## Alterações desta entrega

- Resumo da Ficha: adicionada exportação manual em JSON para o fluxo de importação manual do módulo Raziel Integration. O botão reutiliza o mesmo construtor de payload empregado pela sincronização direta com o Foundry.
- Login: ampliado o cartão, os campos e a hierarquia tipográfica; refinamento visual sem alteração do fluxo de autenticação.
- Backup: exportação passa para o formato `raziel-compendium-backup` versão 2 e inclui talentos, pré-requisitos, requisitos entre árvores, progresso, ápices, nível global, conteúdos especiais, proprietários de efeitos, efeitos, interações e atividades.
- Backup: exportação com paginação de 1.000 registros para não truncar tabelas que ultrapassem o limite padrão de consulta.
- Restauração: compatibilidade com backups v1 e v2. Backups v1 são bloqueados quando há dados nas estruturas novas que eles não representam, evitando exclusão em cascata e perda silenciosa.
- Snapshots: novos snapshots passam a usar o payload v2; a prévia mostra as contagens das novas estruturas e continua lendo snapshots v1.
- Histórico: consulta paginada de 20 eventos, sem limite visual de 30 registros. Inclui filtros e rótulos para efeitos, vínculos, interações, atividades, conteúdos especiais, ápices, progressão global, restaurações e snapshots.
- Banco: adicionados gatilhos de auditoria para as novas estruturas e removido o descarte automático dos eventos antigos do histórico.

## Aplicação

1. Faça um backup atual do banco antes de aplicar a migração.
2. No Supabase SQL Editor, execute `supabase/migrations/202611160003_compendium_backup_history_v2.sql`.
3. Publique a nova versão do site.
4. Gere um novo backup JSON v2 e crie um novo snapshot para estabelecer um ponto de restauração completo.
5. Valide exportação, prévia e restauração em ambiente controlado antes de depender do fluxo em produção.

## Compatibilidade e limites

- A migração não foi executada automaticamente; precisa ser aplicada manualmente no Supabase.
- Snapshots antigos v1 continuam listáveis e sua prévia continua funcionando. Se já existirem efeitos, atividades ou conteúdos especiais no banco, a restauração de um snapshot v1 será recusada por segurança. Gere um snapshot v2 antes de futuras restaurações.
- Backups não incluem dados operacionais ou sensíveis de autenticação e integração: `foundry_integrations`, `foundry_pairing_codes`, `foundry_sync_requests`, `user_roles`, `admin_users`, `admin_activity_history` e `progression_snapshots`.
- O histórico antigo já eliminado pela política anterior de retenção de 30 eventos não pode ser recuperado. A partir da migração, novos eventos deixam de ser descartados automaticamente.
- O build completo não pôde ser confirmado neste ambiente porque a instalação das dependências via `npm ci` expirou; a verificação sintática TypeScript/TSX foi executada separadamente.
